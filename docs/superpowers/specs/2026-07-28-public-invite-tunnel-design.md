# 公网邀请链接 + 座位交换 + 叠层规则修正

日期：2026-07-28  
状态：待实现

## 目标

让主机双击启动后，能把**邀请链接**发给朋友；朋友用浏览器打开即可入座，无需安装任何东西。  
同时补齐开局前的**先手/后手座位展示与交换**，并修正错误的叠层规则。

## 非目标

- 固定域名、账号登录、多房间大厅、观战
- 云服务器长期部署
- 朋友端安装客户端 / 插件 / 隧道工具
- 复杂断线重连（保持现有：断线空出座位）

## 背景

当前原型仅局域网：Node HTTP + WebSocket 单房间，终端打印 LAN 地址。  
WebSocket 已按 `location.host` 连接，公网 HTTPS 域名下可自动走 `wss`。

## 方案选型

采用 **Cloudflare 快速隧道（cloudflared）**：

- 仅主机需要隧道进程；朋友只开浏览器
- 免费、通常无需注册；每次启动得到临时 `https://xxxx.trycloudflare.com`
- 关黑窗口即停服，链接失效（符合「临时分享」）

## 架构

```
主机 PC                              朋友
开始游戏.bat
  ├─ node server.js (:3000)
  └─ cloudflared → 公网 HTTPS
创建房间 → 生成 inviteToken
复制邀请链接发出 ──────────────────► 浏览器打开 /?invite=TOKEN
                                     自动入座后手（B）
双方 ready：可交换先手后手
任一方「开始对局」→ 现有 layout / action
```

## 启动流程

1. 双击 `开始游戏.bat`（或等价一键入口）
2. 启动游戏服监听 `0.0.0.0:3000`
3. 若项目内无 `cloudflared`，首次自动下载到项目本地目录（仅主机）
4. 启动快速隧道，解析公网 base URL，存于服务端内存
5. 终端打印：本机地址、公网地址
6. 浏览器可仍打开本机页；分享用公网邀请链接

隧道失败时：本机/局域网仍可玩；UI 提示「公网分享不可用」，不阻塞开房。

## 房间阶段与座位

在现有 `waiting` → `layout` → `action` → `ended` 之间插入 **`ready`**：

| 阶段 | 含义 |
|------|------|
| `waiting` | 仅主机（先手）在座，等待邀请加入 |
| `ready` | 双方到齐，尚未开局；可交换座位 |
| `layout` / `action` / `ended` | 与现有一致 |

座位语义：

- **先手** = 玩家 A = 深色
- **后手** = 玩家 B = 浅色

流程：

1. 主机「创建房间」→ 入座先手，进入 `waiting`，展示邀请链接与复制按钮
2. 朋友打开 `/?invite=<token>` → 校验通过后入座后手 → 进入 `ready`（**不**立刻 `startMatch`）
3. `ready` 时双方可见座位卡片；任一方可点「交换先手后手」→ 两人座位对调（颜色/先后手一起换）
4. 任一方点「开始对局」→ `startMatch` → `layout`
5. 进入 `layout` 后禁用交换；「再来一局」回到双方仍在座的 `ready`（可再次交换后再开始）

## 邀请链接

- 主机创建房间时生成本局 `inviteToken`
- 邀请 URL：`{publicBase || pageOrigin}/?invite={token}`
- 公网 base 未就绪时显示「公网链接准备中…」，就绪后自动更新；局域网下可用本机/LAN origin 生成同结构链接
- 朋友页检测到 `invite` 查询参数 → WebSocket 连通后自动发送带 token 的 join
- 失败（无房、token 错、已满、主机已关）→ 留在大厅并显示中文错误

朋友**永远不需要**下载 cloudflared 或其它工具。

## 协议增量（WebSocket）

在现有消息上扩展（字段名实现时可微调，语义固定）：

- `create` → `assigned` 增加 `inviteUrl`（或 `inviteToken` + 客户端拼 URL）、可选 `publicBase`
- `join` 增加可选 `inviteToken`；带 invite 的自动加入走同一 join
- 新增 `swapSeats`：仅 `ready` 且双方在座时合法；广播新座位映射与 `state`
- 新增 `start`：仅 `ready` 时合法；服务端 `startMatch` 后广播
- `restart`：结束后回到 `ready`（双方仍在座），而不是直接再进 layout（若仅一人在座则回 `waiting`）

## UI 增量

- 大厅/准备区：先手座位、后手座位（显示占用者或「空」）
- 主机：复制邀请链接
- `ready`：`交换先手后手`、`开始对局`
- 保留局域网提示；公网可用时优先展示邀请链接

## Bug 修正：叠层规则

### 问题

当前实现仅用 `destH + 1 <= 3`，导致：

1. **一层可踩到二层成三层**（矮爬高）——实玩确认非法  
2. **三层顶可直接落到一层或空地**——原文未写清；采用统一升降约束后也不允许

### 正确规则（统一公式）

移动只移源堆**顶层 1 枚**。记：

- `startH` = 移动前源堆高度
- `destH` = 移动前目标堆高度

须同时满足：

1. `destH + 1 <= 3`（结果不超过三层）
2. **`startH - 1 <= destH <= startH`**（只能平迁或下降恰好一层；不可矮踩高，也不可从高层直接掉两级）

因此：

| startH | 合法 destH | 说明 |
|--------|------------|------|
| 1 | 0, 1 | 可到空地或一层；不可上二层 |
| 2 | 1, 2 | 可到一层或二层成三；**不可落到空地** |
| 3 | 2 | **只能落到二层**（再成三）；不可到一层或空地 |

- 二层 → 二层：合法，结果三层  
- 三层顶四周若无二层：该顶子暂时无法移动（可接受的「登顶承诺」）  
- 叠到已满三层：非法  

服务端 `applyMove` 与客户端移动高亮必须一致。测试至少覆盖：一层不能上二层；二层可上二层；二层不能落空地；三层只能上二层。  
错误文案用明确中文（如「只能平迁或下降一层」）。

## 错误处理

| 情况 | 行为 |
|------|------|
| cloudflared 下载/启动失败 | 本机可玩；提示公网不可用 |
| 邀请 token 无效/过期/满员 | 朋友端中文错误，不入座 |
| 非 ready 时 swap/start | 服务端拒绝 |
| 主机关窗口 | 隧道与游戏停止，链接失效 |

## 成功标准

- [ ] 主机一键启动后能复制公网邀请链接
- [ ] 朋友仅用浏览器打开链接即可入座后手
- [ ] 开局前双方都能交换先手后手，再开始对局
- [ ] 叠层统一公式成立：一层不能上二层；二层可上二层成三、不能落空地；三层只能上二层
- [ ] 隧道失败不阻断局域网对局
